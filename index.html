UI Architecture

IntermediateFrontend
Narrative

UI Architecture defines how the presentation layer is structured, how state flows, how components communicate, and how the UI scales as teams and features grow.

A solid UI architecture answers: Where does state live? How do components compose? How are concerns separated? How do we ship independently?

Modern UI architecture rests on five pillars: Component model, State management, Routing & navigation, Data fetching & caching, and Build & delivery.

Think in layers: *Presentation* (dumb components) → *Container/Feature* (smart, data-aware) → *Domain* (entities, use cases) → *Infrastructure* (API clients, storage). Cross-cutting concerns (auth, i18n, theming, telemetry, error boundaries, feature flags) sit in shared providers.

Real-world case study

Netflix uses a component-driven architecture with Gibbon (their custom rendering engine for TVs) and React for web. Teams own vertical slices (Browse, Player, Profile). A shared design system (Hawkins) ensures consistency. They preload data via GraphQL Federation so the UI is data-ready before mount. Result: sub-second TTI on 1000+ device types.

Diagram
Questions & Answers (5)
What are the core pillars of UI architecture?

Component model, state management, routing, data fetching/caching, build & delivery pipeline, plus cross-cutting concerns like auth, i18n, theming, telemetry.

When do you choose a monolithic SPA vs microfrontends?

Monolith for ≤2 teams, shared release cadence, tight UX coupling. Microfrontends when independent teams, independent deploys, and isolated tech stacks outweigh integration costs.

How do you prevent prop drilling at scale?

Compose context providers, colocate state, use selector hooks, or adopt an atomic state library (Zustand, Jotai) for cross-cutting state.

What is the role of a design system in UI architecture?

It enforces visual + behavioral consistency, accelerates delivery, and decouples product teams from low-level UI decisions through versioned, accessible primitives.

How do you handle error boundaries across a large app?

Wrap each route + each async-island in an ErrorBoundary; log to telemetry; provide graceful fallback UI; never let a single feature crash the shell.

Practice exercise
Practice exercise: Design the UI architecture for a multi-tenant SaaS dashboard with 4 teams, dark/light themes, role-based menus, and offline support. List your layers, state strategy, and how teams release independently.

MERN Stack Architecture

IntermediateFull-stack
Narrative

MERN = MongoDB + Express + React + Node. It is a JavaScript-everywhere stack, ideal for CRUD-heavy SaaS, real-time apps, and rapid prototyping.

A production MERN architecture typically has: React SPA → CDN, Node/Express API behind a load balancer, MongoDB replica set with sharding, Redis for sessions & cache, WebSockets via Socket.io, and a job queue (BullMQ) for async work.

Layering on the backend: *Routes → Controllers → Services → Repositories → Mongoose Models*. Validation at the edge (Zod/Joi), domain logic in services, persistence in repositories.

Real-world case study

A fintech onboarding portal handles 50k KYC submissions/day. React frontend served from CloudFront. Express API runs in 12 ECS tasks behind an ALB. MongoDB Atlas with M30 sharded cluster, 3 replicas per shard. Redis caches feature flags. BullMQ processes document OCR via Tesseract workers. Average response time: 180 ms p95.

// Express + Mongoose repository pattern
class UserRepo {
  constructor(model) { this.model = model; }
  findById(id) { return this.model.findById(id).lean(); }
  create(data)  { return this.model.create(data); }
}
class UserService {
  constructor(repo, mailer) { this.repo = repo; this.mailer = mailer; }
  async register(dto) {
    const user = await this.repo.create(dto);
    await this.mailer.send(user.email, 'welcome');
    return user;
  }
}
Questions & Answers (4)
How do you scale a Node.js API horizontally?

Stateless services, sticky-session-free design, shared cache (Redis), load balancer (ALB/NGINX), cluster mode or container replicas, and externalized sessions/JWT.

When would you NOT pick MongoDB?

When you need strict ACID across many entities, complex multi-row joins, or strong relational integrity — pick PostgreSQL instead.

How do you handle file uploads in MERN?

Use multipart/form-data with multer, stream directly to S3 via presigned URLs, store only the URL + metadata in MongoDB.

How do you secure an Express API?

Helmet, rate limiting, CORS allow-list, input validation, JWT/refresh-token rotation, parameterized queries, secret manager, audit logs.

Practice exercise: Design a MERN architecture for a real-time collaborative whiteboard with 100k concurrent users. Address state sync, presence, persistence, and scaling.

Architecture Decision Records (ADR)

BeginnerProcess
Narrative

An ADR is a short markdown document that captures a single architectural decision, the context that drove it, the options considered, and the consequences. ADRs make architecture *visible, reviewable, and historical*.

A canonical ADR has: Title, Status (Proposed/Accepted/Deprecated/Superseded), Context, Decision, Consequences (positive & negative), and optionally Alternatives.

Store ADRs in the repo under /docs/adr/NNNN-title.md. Number them sequentially. Never edit an accepted ADR — supersede it with a new one.

Real-world case study

Spotify publishes ADRs per squad. When they migrated their event pipeline from Kafka REST proxy to native clients, ADR-0042 captured: context (latency), options (REST vs native vs gRPC), decision (native), consequences (ops complexity, +client libraries to maintain). Two years later ADR-0107 superseded it when they moved to Pub/Sub on GCP.

Diagram
Code
# ADR-0007: Use PostgreSQL for the Orders service
## Status
Accepted (2025-04-12)
## Context
Orders require strong consistency, joins across line items, and reporting.
## Decision
Adopt PostgreSQL 15 on Aurora with read replicas.
## Consequences
+ ACID, mature tooling, JSONB hybrid.
- Sharding is harder than Mongo if we grow >5 TB.
## Alternatives considered
- MongoDB (rejected: weak joins, eventual consistency).
- DynamoDB (rejected: query flexibility).
Questions & Answers (3)
What makes a *good* ADR?

Single decision, ≤2 pages, written in present tense, captures *why* not just *what*, lists alternatives and trade-offs, and is reviewed by stakeholders.

Should you edit an accepted ADR?

No. Create a new ADR that supersedes it. The history of decisions is as valuable as the current state.

Who owns ADRs?

The team making the decision; the architect curates and reviews. PRs to /docs/adr trigger architecture review.

Practice exercise
Practice exercise: Write an ADR proposing a switch from REST to GraphQL for your mobile BFF. Include context, 3 alternatives, and at least 4 consequences (2 positive, 2 negative).

TOGAF & Enterprise Architecture

AdvancedEnterprise
Narrative

TOGAF (The Open Group Architecture Framework) is the most widely adopted EA framework. Its heart is the ADM (Architecture Development Method) — a cyclic, 8-phase process (A–H) plus a Preliminary phase and Requirements Management at the center.

The four architecture domains: Business, Data, Application, Technology (BDAT).

Outputs include the Architecture Vision, Baseline & Target Architectures, Gap Analysis, Roadmap, and Architecture Repository. Governance is enforced through an Architecture Board and Compliance Reviews.

Real-world case study

A global bank used TOGAF ADM to consolidate 14 legacy core-banking systems into 3. Phase A defined the vision (single customer view). Phases B–D produced target BDAT. Gap analysis identified 87 systems to retire. The 5-year roadmap saved $120M in licensing and reduced MTTR by 60%.

Diagram
Questions & Answers (3)
What are the four TOGAF architecture domains?

Business, Data, Application, Technology (BDAT).

What is the difference between Baseline and Target architecture?

Baseline = current state. Target = desired future state. Gap analysis bridges them and drives the roadmap.

What is the role of the Architecture Board?

Approves principles, reviews compliance, arbitrates trade-offs, owns the Architecture Repository.

Practice exercise
Practice exercise: Apply TOGAF Phase A to your organization: write a one-page Architecture Vision for migrating from on-prem to cloud, identifying stakeholders, drivers, and high-level capabilities.

System Design Fundamentals

IntermediateCore
Narrative

System design is the discipline of translating requirements into a scalable, reliable, observable, and cost-effective topology.

A repeatable framework:

1. Clarify functional + non-functional requirements (RPS, latency, data volume, SLA).

2. Estimate capacity (storage, bandwidth, QPS).

3. API contract (REST/GraphQL/gRPC, idempotency).

4. Data model (entities, access patterns, consistency).

5. High-level design (clients, edge, services, data stores, async).

6. Deep dives (hotspots, bottlenecks, failure modes).

7. Trade-offs (CAP, cost vs latency, build vs buy).

Real-world case study

Designing a URL shortener at 10k writes/s, 100k reads/s: base62 encoding over 64-bit auto-increment, Redis LRU cache hit-rate ~95%, MySQL with read replicas, CDN for hot links, async analytics via Kafka, p99 redirect < 30 ms.

Diagram
Questions & Answers (3)
State the CAP theorem.

In a distributed system you can guarantee only two of Consistency, Availability, Partition tolerance. Since partitions are unavoidable, the real trade-off is CP vs AP.

What is the difference between latency and throughput?

Latency = time per request. Throughput = requests per unit time. Optimizing one can hurt the other (batching ↑ throughput but ↑ latency).

How do you estimate capacity for a new system?

Daily Active Users × actions/user × payload size → QPS, bandwidth, storage growth/yr; add 2-3× headroom for peaks and growth.

Practice exercise
Practice exercise: Design Twitter's timeline service for 300M MAU. Choose fan-out-on-write vs read, justify cache strategy, and define your SLOs.

Design Patterns for Architects

IntermediateCore
Narrative

Beyond GoF, architects rely on distributed-system patterns: Circuit Breaker, Bulkhead, Retry-with-backoff, Saga, CQRS, Event Sourcing, Outbox, Strangler Fig, Sidecar, Ambassador, API Gateway, BFF.

Pick patterns by *force*, not fashion: each pattern solves a specific tension (e.g., Saga resolves distributed-transaction vs availability).

Real-world case study

Uber Eats uses the Saga pattern for order placement: 5 services (Order, Restaurant, Payment, Courier, Notification) coordinate via an orchestrator. Compensating actions roll back if any step fails. Outcome: 99.95% order success rate without distributed transactions.

Diagram
Questions & Answers (3)
When do you use Circuit Breaker?

To stop calling a downstream that is failing, give it time to recover, and protect upstream resources from cascading failures.

CQRS vs CRUD?

CQRS splits read and write models; use when read/write workloads diverge sharply or when you need projections, event sourcing, or different consistency models.

What problem does the Outbox pattern solve?

Atomically publishing an event AND persisting state without distributed transactions, by writing the event to a local DB outbox table consumed by a relay.

Practice exercise
Practice exercise: Map 5 patterns to a checkout flow that spans Cart, Pricing, Inventory, Payment, and Fulfillment. Justify each choice.

Cloud Architecture (AWS / Azure / GCP)

AdvancedCloud
Narrative

Cloud architecture is the art of composing managed services to meet 5 pillars: Operational Excellence, Security, Reliability, Performance, Cost Optimization (AWS Well-Architected; Azure & GCP have parallels).

Reference building blocks: Compute (EC2/Lambda/ECS/Fargate, App Service, GKE), Storage (S3/Blob/GCS), Database (RDS/Cosmos/Spanner), Networking (VPC/VNet, Transit Gateway, Cloud Interconnect), Identity (IAM/Entra), Observability (CloudWatch/Monitor/Operations).

Real-world case study

A media company runs live-streaming on AWS: CloudFront → MediaLive → MediaPackage → S3 origin; viewers authenticated with Cognito; per-stream metrics in CloudWatch; spend optimized via Savings Plans and Spot for transcoders. 4M concurrent viewers, $0.012/viewer-hour.

Diagram
Questions & Answers (3)
Multi-AZ vs Multi-Region?

Multi-AZ = HA within one region (single-digit ms). Multi-Region = DR + global latency, but costs ↑ and consistency becomes eventual.

When to pick serverless (Lambda) vs containers?

Lambda for event-driven, spiky, short-lived workloads; containers for long-running, stateful, or steady-load services where cold-starts and 15-min limits hurt.

How do you control cloud cost?

Tagging + cost-allocation, right-sizing, Savings Plans/Reserved, Spot, autoscaling, lifecycle policies on storage, FinOps reviews.

Practice exercise: Design a multi-region active-active e-commerce platform on AWS with RPO=0 and RTO<60s. Choose data store, replication, and DNS strategy.

Microservices Architecture

AdvancedDistributed
Narrative

Microservices decompose a system into independently deployable services aligned to business capabilities (DDD bounded contexts). Each service owns its data, its API, and its release cadence.

Success requires investment in: service discovery, API gateway, observability (traces/metrics/logs), CI/CD per service, contract testing, schema evolution, and a strong platform team.

*Don't* start with microservices — start with a modular monolith and extract when team/throughput pain justifies it.

Real-world case study

Amazon runs ~10,000 microservices; each owned by a 2-pizza team. Internal mandate (2002): every team exposes data via service interfaces, no shared DB. Result: enabled AWS itself, and >150 deploys/second platform-wide.

Diagram
Questions & Answers (3)
What is a bounded context?

A DDD concept: an explicit boundary within which a domain model is defined and applicable. Each microservice typically owns one bounded context.

How do microservices communicate?

Sync via REST/gRPC, async via events (Kafka/Pub-Sub). Prefer async for cross-context flows to reduce coupling.

What is a distributed monolith?

Microservices that must be deployed together because of tight coupling — worst of both worlds. Caused by shared DBs or sync chains.

Practice exercise
Practice exercise: Identify 4 bounded contexts for a hotel-booking platform and define the events each publishes.

DevOps & CI/CD Architecture

IntermediateDelivery
Narrative

DevOps unifies dev + ops via automation, measurement, and shared ownership. A modern CI/CD pipeline: commit → lint/test → build → SAST/SCA → package → deploy to env → smoke → progressive rollout → observe → rollback if SLO breach.

Key metrics: DORA — Deployment Frequency, Lead Time, Change Failure Rate, MTTR. Elite teams: >1 deploy/day, <1 hr lead, <15% CFR, <1 hr MTTR.

Real-world case study

Etsy deploys 50+ times/day. Trunk-based dev, feature flags (LaunchDarkly-style), canary 1% → 10% → 100% with automated SLO gates. A bad deploy is rolled back in <90s by their Deployinator tooling.

Diagram
Questions & Answers (3)
Blue-Green vs Canary?

Blue-Green: full new env, instant switch, easy rollback, double infra cost. Canary: gradual % traffic to new version, finer risk control, needs SLO-based gates.

What is GitOps?

Declarative infra/app state in Git; an agent (ArgoCD/Flux) reconciles cluster state to Git. Audit + rollback = git revert.

How do you secure a CI pipeline?

Signed commits, ephemeral runners, OIDC to cloud (no static keys), secret scanning, SBOM generation, image signing (cosign), policy-as-code (OPA).

Practice exercise
Practice exercise: Design a CI/CD pipeline for a 30-service microservices platform with mandatory security gates and 99.9% deploy success.

Security Architecture

AdvancedSecurity
Narrative

Security architecture applies defense in depth across identity, network, application, data, and operations.

Core models: Zero Trust (never trust, always verify), Least Privilege, Secure by Default, Shift Left.

Frameworks: NIST CSF, ISO 27001, OWASP ASVS, STRIDE threat modeling.

Architect concerns: AuthN/AuthZ (OAuth2/OIDC/SAML), secret management (Vault/KMS), encryption (TLS 1.3, at-rest), network segmentation, WAF, DDoS, audit, SIEM, IR runbooks.

Real-world case study

Google BeyondCorp eliminated the VPN by treating every request as untrusted, regardless of network. Device + user identity drive access via a context-aware proxy. Result: employees work securely from anywhere; lateral-movement risk near zero.

Diagram
Questions & Answers (4)
OAuth2 vs OIDC?

OAuth2 = authorization (delegated access tokens). OIDC sits on top to add authentication (id_token = JWT with user identity).

Symmetric vs asymmetric encryption — when to use which?

Symmetric (AES) = fast, for bulk data. Asymmetric (RSA/ECC) = key exchange, signatures. Hybrid: asymmetric to share an AES key, symmetric for payload.

What is STRIDE?

Threat model categories: Spoofing, Tampering, Repudiation, Info disclosure, DoS, Elevation of privilege.

How do you protect against SSRF?

Validate/allow-list outbound URLs, block link-local & metadata IPs (169.254.169.254), enforce egress proxy, disable redirects to private ranges.

Practice exercise
Practice exercise: Threat-model an online banking login using STRIDE. List ≥2 threats per category and a mitigation each.

Performance Engineering

AdvancedNFR
Narrative

Performance is a feature. Architects define SLIs/SLOs, measure with RUM + synthetics, profile hot paths, and design for the mechanical sympathy of network, CPU, memory, and storage.

Frontend: critical-path CSS, code-splitting, image optimization (AVIF), Core Web Vitals (LCP<2.5s, INP<200ms, CLS<0.1).

Backend: p99 latency budgets, async I/O, connection pooling, caching layers (L1 in-process, L2 distributed, L3 CDN), query plans, N+1 elimination.

Real-world case study

Pinterest cut LCP by 40% by lazy-loading below-the-fold pins, preloading the hero image, and inlining critical CSS. Conversions rose 15%.

Diagram
Questions & Answers (3)
What is the difference between p50, p95, p99?

Percentiles of latency distribution. p99 reflects tail experience — what 1% of users feel — and drives SLO design.

How do you debug high p99 latency?

Distributed tracing → identify slow span → check GC, network, DB locks, cold caches, downstream timeouts; profile CPU/heap; check queue depth.

What is amortized cache invalidation?

Strategies like write-through, write-behind, TTL+jitter, or event-driven invalidation that spread invalidation cost over time to avoid stampedes.

Practice exercise
Practice exercise: Define SLIs/SLOs for a payment API at 5k TPS. Include error budget policy and an alerting strategy.

Scalability & Resilience Patterns

AdvancedNFR
Narrative

Scalability is the ability to handle growth; resilience is the ability to keep working when things break. Both demand stateless services, horizontal scaling, bulkheads, timeouts/retries with jitter, idempotency, graceful degradation, and chaos testing.

Patterns: Auto-scaling, Backpressure, Load Shedding, Rate Limiting, Hedged Requests, Cell-based Architecture.

Real-world case study

AWS runs every service as cells — independent stacks per shard of customers. A bad deploy or noisy neighbor is contained to one cell, blast-radius ≤1/N. This is why an S3 issue in us-east-1 rarely takes down all of S3 globally.

Diagram
Questions & Answers (3)
Vertical vs horizontal scaling?

Vertical = bigger box (limit: hardware). Horizontal = more boxes (limit: coordination). Stateless services favor horizontal.

What is backpressure?

A mechanism by which a consumer signals to a producer to slow down — bounded queues, 429s, or reactive streams. Prevents OOM cascades.

Why is idempotency critical for retries?

Network retries duplicate requests. Without idempotency keys, you double-charge customers or double-ship orders.

Practice exercise: Design auto-scaling for a flash-sale checkout at 100× normal load with <1% error rate.

Event-Driven Architecture

AdvancedDistributed
Narrative

EDA decouples producers from consumers via events on a durable bus (Kafka, Pulsar, EventBridge, NATS).

Event styles: Event Notification (thin, pull details), Event-Carried State Transfer (fat), Event Sourcing (events are the source of truth), CQRS (separate write/read).

Schemas evolve via schema registries (Avro/Protobuf). Delivery: at-least-once + idempotent consumers is the practical default.

Real-world case study

LinkedIn invented Kafka to ingest 7T+ messages/day. Every site interaction emits events consumed by 100s of pipelines (search index, ML features, notifications). Strict schema registry prevents breaking changes.

Diagram
Questions & Answers (3)
Event Sourcing — pros and cons?

+ full audit, time-travel, CQRS-friendly. − schema evolution, eventual consistency, complex queries, replay cost.

At-least-once vs exactly-once delivery?

Exactly-once is expensive and rarely true end-to-end. Design at-least-once + idempotent consumers using dedup keys.

How do you order events across partitions?

Use a partition key (e.g., aggregate id) so all events for one entity land on one partition; cross-partition order is not guaranteed.

Practice exercise
Practice exercise: Model the events for an e-commerce checkout. Define schema, partition key, and consumer responsibilities.

Domain-Driven Design (DDD)

AdvancedModeling
Narrative

DDD aligns code with the business domain through Ubiquitous Language, Bounded Contexts, Aggregates, Entities, Value Objects, Domain Events, and Repositories.

Strategic DDD = context map (partnership, customer/supplier, anti-corruption layer). Tactical DDD = the building blocks.

DDD shines in complex domains (banking, insurance, logistics) and underpins good microservice boundaries.

Real-world case study

A logistics SaaS modeled Shipment as an aggregate root with Leg entities and Address value objects. Domain events (ShipmentDispatched, LegArrived) drive integrations. Refactoring boundaries reduced cross-team coordination meetings by 70%.

Diagram
Questions & Answers (3)
Entity vs Value Object?

Entity has identity (id) that persists through state changes. Value object is immutable, equality by attributes (e.g., Money, Address).

What is an aggregate?

A cluster of entities/VOs treated as one transactional unit with a single root that enforces invariants and is the only entry point.

What is an Anti-Corruption Layer?

A translation layer that protects your domain model from a foreign (often legacy) model's concepts.

Practice exercise
Practice exercise: Identify 3 aggregates and their invariants for a ride-hailing app (Trip, Driver, Rider).

Microfrontend Architecture

AdvancedFrontend
Narrative

Microfrontends extend microservice thinking to the UI. Composition strategies: build-time (npm packages), server-side (SSI/Tailor), edge-side (ESI/Cloudflare Workers), client-side (Module Federation, single-spa, Web Components).

Hard problems: shared state, design consistency, perf (bundle dup), routing, auth propagation, versioning, observability.

Real-world case study

IKEA rebuilt ikea.com with microfrontends per business area (search, PDP, cart). Module Federation shares React + design system. Independent teams deploy ~30 times/day each, with strict perf budgets (LCP<2.5s).

Diagram
Questions & Answers (3)
When NOT to use microfrontends?

Single small team, tight UX coupling, perf-critical SPA — the integration cost outweighs the org benefits.

How do you share state across MFEs?

Prefer URL + events on a shared bus; for cross-MFE state, use a tiny shared store exposed via the shell, avoid global mutable state.

How do you avoid duplicate dependencies?

Module Federation `shared` config, peerDependencies, single React instance enforced via singleton.

Practice exercise: Design a microfrontend strategy for a banking portal with 5 product teams sharing one design system and one auth.

API Design & Integration Patterns

IntermediateIntegration
Narrative

Choose the protocol fitting the consumer: REST (broad, cacheable), GraphQL (flexible reads, mobile/BFF), gRPC (internal, low-latency, strong typing), AsyncAPI (events).

Design principles: resource-oriented URIs, idempotent verbs, versioning (URL or header), consistent error envelope, pagination, filtering, HATEOAS where it helps, OpenAPI as source of truth.

Integration patterns: API Gateway, BFF, anti-corruption layer, webhooks, batch sync, change-data-capture (CDC).

Real-world case study

Stripe's REST API is the gold standard: stable since v1, idempotency keys, expandable objects, cursor pagination, versioned by date header. 99.999% availability.

Diagram
Questions & Answers (3)
REST vs GraphQL?

REST is simple, cacheable, predictable; great for public APIs. GraphQL gives clients shape control, reduces over/under-fetching; needs query cost limits.

How do you version an API?

URL path (/v1/), custom header, or content negotiation. Whatever you pick, document a deprecation policy and dual-run major versions.

What is idempotency in REST?

Repeating the request has the same effect (PUT, DELETE, GET). For POST, use an Idempotency-Key header to make it safe to retry.

Practice exercise
Practice exercise: Design a v1 REST API for a Subscriptions service with create, upgrade, cancel, and webhooks. Include error envelope and idempotency.

Kubernetes & Container Architecture

AdvancedCloud
Narrative

Kubernetes is the de-facto orchestrator: declarative desired state, self-healing, autoscaling, rolling updates.

Architectural building blocks: Pod, Deployment, Service, Ingress, ConfigMap, Secret, HPA/VPA, StatefulSet, DaemonSet, NetworkPolicy.

Architects design multi-tenant clusters (namespaces, quotas, PSP/PSA, OPA Gatekeeper), service mesh (Istio/Linkerd) for mTLS + traffic policy, and GitOps for delivery.

Real-world case study

Shopify runs 200+ clusters, 10k+ namespaces. Cell-based: each shop shard isolated. Spinnaker + ArgoCD for delivery. Custom controllers manage tenant lifecycle. Black Friday: 25M RPS sustained.

Diagram
Questions & Answers (3)
Deployment vs StatefulSet?

Deployment for stateless replicas (interchangeable). StatefulSet for stable network IDs + persistent volumes (DBs, Kafka).

Why use a service mesh?

Uniform mTLS, retries, timeouts, traffic shifting, observability — without changing app code. Cost: complexity, latency, ops.

What is HPA vs VPA vs Cluster Autoscaler?

HPA scales pods on metrics, VPA right-sizes pod resources, CA adds/removes nodes when pods can't schedule.

Strangler Fig & Migration Patterns

AdvancedModernization
Narrative

Coined by Martin Fowler, the Strangler Fig pattern incrementally replaces a legacy system by routing new functionality to new services while strangling the old one. Alternatives: Big Bang (risky), Branch by Abstraction, Parallel Run, Expand-Contract.

Key enablers: Facade/Proxy (NGINX, API GW), Anti-Corruption Layer, Dual-Write + CDC, Feature Flags, Shadow Traffic.

Real-world case study

A 20-year-old monolith insurer used a strangler proxy: each new policy product launched in a new microservice; the proxy routed by URL. Over 4 years 80% of traffic moved off the monolith with zero outages.

Diagram
Questions & Answers (3)
Why not Big-Bang migrations?

Long freeze, all-or-nothing risk, regression explosion, business pause. Incremental wins via Strangler keep value flowing.

What is a Parallel Run?

Run old and new side-by-side, compare outputs, build confidence before cutover (common in finance/risk).

What is Expand-Contract for DB schemas?

Expand: add new columns/tables compatible with both old & new code. Migrate. Contract: remove old columns. Zero-downtime.

Backend-for-Frontend (BFF)

IntermediateIntegration
Narrative

A BFF is a dedicated backend tailored to a specific client (web, iOS, Android, partner). It aggregates downstream services, shapes payloads for the client, handles auth, and absorbs versioning churn.

Benefits: client-optimized payloads, fewer round-trips, decoupled lifecycles. Costs: more services to maintain, risk of logic duplication if boundaries blur (BFF must stay 'thin orchestration', business logic stays in domain services).

Real-world case study

SoundCloud introduced BFFs when mobile traffic exceeded web. Each platform team owns its BFF, ships independently, and tailors GraphQL responses. Mobile payload size dropped 60%.

Diagram
Questions & Answers (2)
BFF vs API Gateway?

Gateway = generic edge (auth, routing, rate limit) shared by all. BFF = client-specific orchestration & shaping. They complement each other.

What's the biggest BFF anti-pattern?

Stuffing domain logic into the BFF, turning it into a distributed monolith. Keep BFF as thin aggregation.

Authentication & Authorization (OAuth2, OIDC, SAML, JWT, SSO)

AdvancedSecurity
Narrative

Authentication proves *who you are*; authorization decides *what you can do*.

- OAuth2: delegated authorization via access tokens. Grants: Authorization Code (+PKCE) for SPAs/native, Client Credentials for server-to-server, Device Code for TVs.

- OIDC: identity layer on OAuth2 adding id_token (JWT).

- SAML 2.0: XML-based SSO, common in enterprise.

- JWT: self-contained signed token. Validate signature, iss, aud, exp, nbf. Keep short-lived; use refresh tokens with rotation + reuse detection.

- SSO unifies AuthN across apps via IdP (Okta, Entra, Auth0, Keycloak).

Real-world case study

A SaaS migrated from custom session cookies to OIDC + JWT (15-min access, 7-day rotating refresh, HttpOnly cookies). Support tickets for 'logged out unexpectedly' dropped 80% and they enabled enterprise SSO in days.

Diagram
Questions & Answers (4)
Why PKCE?

Protects public clients (SPAs, mobile) from auth-code interception. Required by OAuth 2.1 for all clients.

Where do you store JWTs in a browser?

Prefer HttpOnly + Secure + SameSite cookies. Avoid localStorage (XSS-stealable).

Access vs ID vs Refresh token?

Access = call APIs (short). ID = user identity (OIDC). Refresh = obtain new access (longer, rotated).

RBAC vs ABAC?

RBAC: roles → permissions (simple, coarse). ABAC: attributes (user, resource, env) evaluated by policies (fine-grained, e.g., OPA).

Resilience Engineering & Chaos

AdvancedNFR
Narrative

Resilience engineering accepts that failure is inevitable and engineers for graceful degradation. Tools: timeouts, retries with jitter, circuit breakers, bulkheads, fallback responses, load shedding, queue-based load leveling.

Chaos engineering (Netflix Simian Army) intentionally injects failures (instance kills, latency, DNS errors) in production to validate hypotheses about system behavior.

Real-world case study

Netflix runs Chaos Monkey daily in prod, killing random instances; services that can't survive are rewritten. Their stack survived an entire AWS region outage in 2012 because of this discipline.

Diagram
Questions & Answers (2)
Why add jitter to retries?

Prevents thundering-herd retry storms after a downstream recovers. Use full-jitter exponential backoff.

Bulkhead vs Circuit Breaker?

Bulkhead isolates resources (thread pools, connections) so a slow downstream cannot exhaust everything. Circuit breaker stops calls quickly when a downstream fails.
